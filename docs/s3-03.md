# S3-03 — Check-in khách

Nhánh độc lập từ nền chung c01e927; không chứa thao tác không đến hoặc hoàn tác S3-06.
Nền chung chỉ gồm schema lịch hẹn, audit và cookie/JWT; dùng cùng lịch sử migration để hai nhánh có thể tích hợp.

Lễ tân/Chủ tiệm/Admin đăng nhập rồi mở /CheckIn. Chỉ lịch Confirmed được check-in trong [-60,+60] phút.
Lưu CheckedInAt theo UTC, hiển thị UTC+7; quá 15 phút ghi số phút đến muộn.
Thợ nhận SSE tức thời qua /StylistNotifications; lịch sử thông báo được lưu và tải lại khi reconnect.
Chủ tiệm/Admin liên kết tài khoản Thợ ở /StylistLinks. Tài khoản mẫu được seed liên kết sẵn.
API JWT: POST /api/appointments/{id}/check-in. Thao tác form cần CSRF token.

Kiểm thử: dotnet test SalonManagement.Tests/SalonManagement.Tests.csproj
HTTP server thật sau build: python tools/test_s3_03_http.py
SQL Server: DatabaseProvider=SqlServer và dotnet ef database update --project SalonManagement.
SQLite demo cần database mới (EnsureCreated không nâng cấp database cũ).
SSE hiện dùng một tiến trình; nhiều instance cần bus phân tán. Đã đối chiếu develop d9282f4 và kiểm thử HTTP trên SQL Server LocalDB.
Staging vẫn cần xác minh tại môi trường triển khai.
Dùng JWT/cookie salon.accessToken và SessionPrincipalValidator của nhóm; không thay AuthController/auth.js.
Đăng ký module ở CheckInServiceRegistration.cs, mapping dữ liệu ở AttendanceDbContext.cs.
Model và controller đi theo cấu trúc Models/Appointments, Controllers/Attendance.
Route check-in /api/appointments/{id}/check-in tách khỏi /api/reception/... của S3-04.
Ưu tiên tích hợp PR vào develop; không ghi đè file xác thực hoặc snapshot của nhóm bằng bản cũ.
Kiểm thử hiện tại: 156 test .NET đạt và kiểm thử HTTP SQL Server đạt.
